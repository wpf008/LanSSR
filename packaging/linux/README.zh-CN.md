# LanSender / LanReceiver · 麒麟桌面 V10 SP1 ARM64 安装说明

2.0.23 安装包面向麒麟桌面 V10 SP1 的 ARM64 / aarch64 系统，适用于飞腾、鲲鹏桌面。安装后提供两个独立应用：**LanSender** 用于发送文件，**LanReceiver** 用于连续接收文件。应用使用原生窗口与 OpenGL，不依赖 WebView。

界面根据图形环境自动选择渲染方式：桌面 OpenGL 2.0 及以上使用原渲染方式，仅提供桌面 OpenGL 1.1 时使用兼容渲染。软件渲染速度可能较慢，可在发送端设置页选择 100 毫秒间隔。

## 安装与启动

在安装包所在目录执行：

```sh
sudo dpkg -i LanSSR_2.0.23_arm64.deb
```

已有 2.0.x 时，直接执行上述命令覆盖升级即可；旧版 2.0.14 因缺少 `zenity` 未完成配置时也可直接升级，无需先卸载、安装 `zenity` 或强制安装。新版下载文件名前缀统一为 **LanSSR**，系统内部包名仍为 `lanbridge`，以便兼容升级和卸载。

`dpkg -i` 直接安装本地文件，适合断网机器。若提示缺少依赖，请从对应麒麟桌面 V10 SP1 ARM64 的安装介质或同版本官方软件源带入依赖包，再安装这些本地依赖和本应用；不要混装 Debian、Ubuntu 等其他发行版或其他架构的软件包。断网时 `apt` 无法下载缺少的包，图形安装器也可能显示“无法下载软件包文件”。本安装包未捆绑全部系统运行库，完整依赖可用以下命令查看：

```sh
dpkg-deb -f LanSSR_2.0.23_arm64.deb Depends
```

安装后桌面自动生成 **LanSender**、**LanReceiver** 两个可执行应用图标，应用菜单也使用这两个名称，不附加“发送端”或“接收端”。通过 `sudo` 安装时为当前用户创建图标；图形安装器安装时为已有普通桌面用户创建，支持中文“桌面”、英文 `Desktop` 和自定义 XDG 桌面路径，也可以在终端执行同名命令。已有同名自定义快捷方式不会被覆盖，系统明确关闭桌面目录时不会创建桌面文件。

Linux 版使用内置文件和目录选择器，在程序界面中选择待发送文件或接收保存目录，无需 `zenity` 或文件选择门户。

## 使用

1. LanReceiver 需要截取含有发送画面的屏幕；X11 / Xorg 会话可以直接截屏，Wayland 会话使用可用的桌面原生截屏接口、截屏协议或桌面门户。2.0.22 增加 UKUI / KWin 原生接口，兼容没有 wlroots screencopy 协议的麒麟桌面，详细说明见下文。
2. LanReceiver 默认保存到系统桌面，点击“设置”可选择目录和深浅主题，然后点击“开始接收”。接收完成后继续等待下一份文件，本次历史列表可滚动，点击文件名可打开所在位置。
3. LanSender 选择文件后点击“发送文件”。两端水印默认开启，在主界面切换且必须保持一致；接收端水印开关位于“开始接收”和“停止接收”之间。发送端设置页可调整深浅主题和 30 / 50 / 100 毫秒帧间隔，默认 50 毫秒；30 毫秒较快，100 毫秒适合性能较弱或出现丢帧时使用。
4. 发送窗口靠左约占工作区 60% 宽、80% 高；接收窗口靠右约占 40% 宽、80% 高。两端均显示当前传输速度，等待时速度为 0 B/s。
5. LanSender 主界面可点击“全屏 / 退出全屏”或按 F11 切换，Esc 退出全屏；文件选择器打开时 Esc 先关闭选择器。全屏扩大每帧容量，建议发送前开启；传输中切换会重新校准并从头发送。实际速度仍受截图、图像解析和显卡性能限制。
6. 传输画面须完整可见且无遮挡。移动发送窗口或改变画面尺寸会重新校准并从头发送；收到缺失帧提示时可延长间隔并按接收端报告补发。

LanReceiver 仍保留单次终端模式：`LanReceiver --cli`。完整选项可执行 `LanReceiver --help` 查看。程序不读取外置配置文件。

## X11 / Xwayland 图形兼容

部分 ARM 图形驱动通过 GLX 创建窗口后会报告 `GLXBadContextTag`，随后出现 `Failed to call XMapRaised`、`PoisonError` 并退出。2.0.23 在 Linux 实际使用 X11 / Xwayland 窗口后端时优先使用 EGL，避免首先走 GLX；原生 Wayland 窗口和 Windows、macOS 的策略保持原样。内核版本本身不能确定显卡驱动是否兼容。

默认 `auto` 仅在 EGL 显示初始化失败时尝试 GLX，不包含后续配置、上下文、表面或首帧失败后的重试。诊断时可在终端为单次启动指定后端；`egl`、`glx` 均严格使用对应后端，不自动切换：

```sh
LANSSR_GL_BACKEND=egl LanSender
LANSSR_GL_BACKEND=glx LanReceiver
```

取消变量或设置 `LANSSR_GL_BACKEND=auto` 恢复默认策略。该变量仅对 Linux 实际使用的 X11 / Xwayland 窗口生效，不改变接收端的截屏后端。图形环境模拟验证不能替代目标 ARM 显卡的启动、全屏和持续收发验证。

## UKUI 与旧版 Wayland 桌面兼容

2.0.20 在部分麒麟 V10 SP1 桌面会话启动时会报告 `libwayshot-xcap` 的 `UnsupportedVersion` 并退出。该错误来自桌面合成器只提供 xdg-output v1 / v2，而截屏依赖要求 v3；内核版本 `5.4.96-27-kr9a0` 本身不是此次报错原因。

2.0.21 按系统实际支持的版本连接 `wl_output`、xdg-output 和 screencopy 协议，兼容旧版 xdg-output v1 / v2、screencopy v1 / v2，并将不支持的截屏功能作为错误返回，避免启动时 panic。

部分麒麟 V10 SP1 使用 `XDG_SESSION_TYPE=wayland`、`XDG_CURRENT_DESKTOP=UKUI` 和 `ukui-kwin_wayland`，桌面没有 `ZwlrScreencopyManager`，因此 2.0.21 能打开窗口，但点击“开始接收”仍会报告无法截屏。2.0.22 增加 UKUI / KWin 原生 D-Bus 区域截屏接口，优先使用当前桌面支持的后端。无需为这个报错切换 X11 / Xorg，也无需另装 `zenity`；桌面环境是否提供截屏能力不能仅凭内核版本判断。

接收端会复用已经成功的截屏后端和 D-Bus 连接，定位棋盘格后仅截取传输区域。旧版 UKUI 接口每次截屏仍需生成并读取 PNG，实际持续传输速率尚未在目标实机验证，默认 50 毫秒间隔不保证每台机器都能跟上；若出现缺失帧，可将发送端间隔改为 100 毫秒。

旧版 UKUI / KWin 的截屏接口可能触发系统截图通知。若通知遮挡棋盘格，请在系统通知设置中关闭截图通知，或调整窗口使传输区域无遮挡；应用不会自动更改系统通知或安全设置。如果系统拒绝原生截屏接口，接收端会展示具体错误信息。

## 卸载

```sh
sudo apt remove lanbridge
```

卸载会移除自动生成且未被修改的桌面快捷方式，不会删除用户自定义快捷方式、已经接收的文件或用户选择的保存目录。

## 包内容与验证范围

程序安装在 `/usr/lib/lanbridge/`，命令入口在 `/usr/bin/LanSender` 和 `/usr/bin/LanReceiver`，菜单文件与 SVG 图标安装在 `/usr/share/`。安装包不包含后台服务，也不会在安装时自动启动程序。ARM64 构建基于 Debian 11 / glibc 2.31；精确依赖以包内 `Depends` 字段为准。项目与补丁依赖的许可证安装在 `/usr/share/doc/lanbridge/`，其中 `xcap-LICENSE` 为完整 Apache 2.0 许可证，`glutin-winit-LICENSE` 为完整 MIT 许可证。

旧版 Wayland 协议与 UKUI / KWin 截屏接口的兼容性通过模拟环境验证；容器安装与图形启动检查不能替代麒麟 V10 SP1 实机的完整收发与持续速率验证。
