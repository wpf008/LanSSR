# imgBridge

基于屏幕图像传输数据的工具：发送端将数据编码为可视化的格子图案显示在屏幕上，接收端通过屏幕截图实时捕获并解码，最终还原出原始数据。

支持两种传输类型：

- **文件传输**：拖拽文件到发送端界面，点击发送
- **文本传输**：点击"文本"按钮，自动读取发送端系统剪贴板中的文本并发送，接收端收到后自动写回系统剪贴板

传输速度约 500-1000 KB/s，取决于发送端分辨率、格子大小、帧间隔、两端机器性能等因素，单个文件建议不要超过 100MB。

本项目仅用于学习和研究目的，严禁用于任何非法活动。

## 技术栈

- **语言**: Java 8
- **UI**: Swing
- **构建工具**: Maven

## 工作原理

1. **编码**: 发送端将数据（文件字节或文本 UTF-8 字节）按帧切分，每帧编码为屏幕上的格子矩阵。每个格子存储 4 bit 数据，两个格子组成一个字节。
2. **传输**: 发送端逐帧更新屏幕显示，帧与帧之间的间隔可配置。
3. **解码**: 接收端通过持续截取发送端界面区域，对每个格子分析还原数据。
4. **校验**: 每帧包含帧号和 MD5 后 2 字节校验，确保数据完整性。
5. **重组**: 接收端按帧号顺序合并所有帧数据，按传输类型还原为文件或文本。

### 帧格式

发送数据前先发送一帧**信息帧**（声明类型、总帧数、名称），随后逐帧发送**数据帧**。

**信息帧**

| 帧类型(1B) | 总帧数(4B) | 名称 |
|-----------|-----------|------|
| `'f'` = 文件<br>`'t'` = 文本 | 本次传输的总帧数 | 文件模式为文件名；文本模式为空 |

**数据帧**

| 帧号(3B) | MD5 校验(2B) | 数据载荷 |
|---------|-------------|---------|
| 帧序号，从 1 开始 | 载荷 MD5 的后 2 字节 | 分片数据 |

### 编码模式

- **无水印模式**: 格子用该档灰度中点着色（`value*16+8`，灰度 8~248），覆盖 0~255 全区间；解码时按 16 级灰度区间判定（0-15 → 0，16-31 → 1，依次类推），每档上下容错对称 ±8 级
- **水印模式**: 每个格子再分为 2x2 四个子格子，用黑白二值状态表示 4 位二进制，可规避发送端界面上的水印干扰

水印模式会比无水印模式稍微慢一点点。

## 配置说明

`conf/imgBridge.properties`:

| 参数 | 说明 | 默认值 |
|------|------|--------|
| width | 窗口宽度（像素），必须为格子大小的整数倍 | 1440 |
| height | 窗口高度（像素），必须为格子大小的整数倍 | 800 |
| cellSize | 格子大小（像素），水印模式需 >= 4 且为偶数 | 4 |
| interval | 发送端帧间隔（毫秒） | 30 |
| waterMask | 发送端界面是否带水印；为 true 时启用水印模式 | false |

> 发送端与接收端都会加载同一份配置文件（`PicReceiver` 启动时也会读取 `conf/imgBridge.properties`），两端保持相同配置即可正常收发。

## 使用方法

### 构建

```bash
mvn clean package
```

构建后在 `target/` 生成两个可执行 JAR：

- `imgBridge-sender.jar`：发送端，入口为 `com.clong.PicTransmitter`
- `imgBridge-receiver.jar`：接收端，入口为 `com.clong.PicReceiver`

运行需要 Java 8 或更高版本及桌面环境。以下命令均在项目根目录执行；部署到其他电脑时，需同时复制 `conf/imgBridge.properties`，并从包含 `conf/` 的目录启动。

### 发送端

```bash
java -Dsun.java2d.uiScale=1.0 -Dwindows.uiScale=1.0 -jar target/imgBridge-sender.jar
```

运行后出现 Swing 界面，上方按钮自左向右依次为：

| 按钮 | 功能 |
|------|------|
| 发送 | 将已拖入的文件分帧发送 |
| 重置 | 清空已选文件与输入，重新初始化界面 |
| 停止 | 中断当前发送 |
| 文本 | 读取发送端系统剪贴板中的文本并发送 |

**发送文件**：

1. 拖拽文件到界面上方的输入框（显示文件名）
2. 点击 **发送** 开始传输，进度显示在"x/y"标签上
3. 如需补发缺失帧，在第二行输入框中填写帧号（支持逗号分隔与区间，如 `1,3-5,8`），再点击 **发送** 仅补发指定帧

**发送文本**：

1. 先在发送端电脑上复制好要发送的文本
2. 点击 **文本** 按钮，文本将以 UTF-8 字节流分帧发送（不做 base64 编码）

### 接收端

```bash
java -Dsun.java2d.uiScale=1.0 -Dwindows.uiScale=1.0 -jar target/imgBridge-receiver.jar
```

接收端启动后自动执行：

1. 读取 `conf/imgBridge.properties`，同步水印模式等配置
2. 扫描所有显示器，寻找发送端的格子界面
3. 实时截图解码；超过 3 秒未解析到新帧时，在控制台打印缺失帧号（最多 100 个）
4. 全部帧接收完成后自动处理：
   - 文件传输 → 按信息帧中的文件名保存到接收端当前目录
   - 文本传输 → UTF-8 解码后写入系统剪贴板，控制台打印收到的文本长度

### 典型执行流程

1. 先运行发送端，拖入文件（或复制好文本）
2. 再运行接收端，等待其自动扫描并锁定发送端的格子界面
3. 发送端点击 **发送** 或 **文本**，两端开始传输
4. 全部接收完成后，接收端自动保存文件或把文本写入剪贴板
5. 若存在缺失帧，接收端控制台会打印缺失帧号（如 `3,7-9`）
6. 在发送端输入框中填入缺失帧号并点击 **发送** 补发，直至接收端输出"结束"

## 构建产物说明

项目没有第三方运行时依赖，使用 `maven-jar-plugin` 一次生成发送端和接收端两个 JAR。两个 JAR 均包含完整项目类，各自设置对应的 `Main-Class`，可直接通过 `java -jar` 启动。

## 隔离环境部署

有的隔离环境的设备无法直接拷入程序，可结合另一个项目 **typist**：先把本项目源码压缩，再通过键盘输入的方式把代码送进隔离环境，最后在目标机器上编译运行。
